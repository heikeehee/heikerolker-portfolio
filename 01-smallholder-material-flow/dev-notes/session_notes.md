## What I Learned — Best Practice Changes for Future Projects

### Things to do from day one (not retrofit later)

1. **Separate clean/ impute/ from the start.**
   Assumption logic (hardcoded rates, gap-filling rules) does not belong in cleaning scripts.
   Clean = structural fixes only. Impute = analytical decisions with documented sources.
   I retrofitted this split — it cost multiple sessions. Start with it.

2. **Build the household spine as the first clean script.**
   `household_roster.R` should always be script 01 in `clean/`. Every other section joins to it.
   I added it late — the pipeline ran without it, which masked the missing spine logic.

3. **Write the reference file (item_groups.csv) before writing analysis scripts.**
   The MFA group structure needs to be settled before `06_mfa_input.R` can be correct.
   I wrote the analysis script before the reference file was complete — caused multiple rewrites.

4. **Commit `mfa_flow.R` (or equivalent utility) early.**
   `mfafun()` and `sankey()` were sitting in archive for the whole project.
   Extracting them to `utils/` on day one would have made `09_outputs.R` much simpler to write.

5. **Export parquet alongside RDS from the start.**
   Adding `arrow::write_parquet()` to every `saveRDS()` call costs nothing.
   Retrofitting it for Python translation is annoying. Just do both every time.

6. **Name columns consistently across all section scripts before joining.**
   Column name mismatches in joins are silent — they produce NAs with no error.
   Agree on a naming convention (snake_case, _kg suffix for weights, etc.) before writing any section script.

### Things that worked well — keep doing these

- `here::here()` throughout — zero path issues
- `stopifnot()` on y4_hhid uniqueness in spine — caught problems early
- `message()` after every join reporting unmatched rows — essential diagnostic
- `# 🚩 FLAG [TYPE]: description` comment convention — easy to grep for
- Two saved versions of MFA input (with and without y4_hhid) — pays off in project 03
- `set.seed()` on all random draws — reproducibility without effort

### Things that were messy — avoid next time

- Having assumption logic scattered across clean/ scripts with `# see impute/` comments that pointed nowhere for weeks
- Firing agents before settling the data structure — especially the processed crops / mass balance question
- Building 07/08/09 before 06 was correct — had to revisit multiple times
- Not reading `03-sankey.R` at the start — it was the canonical flow reference all along

## Key Methodological Decisions — Documented Here for Reference

### Processed crops — anti-double-counting rule
Sold/consumed destination quantities are RAW crop flows only.
Processed product flows (prodsold, prodconsumed) are separate outputs of the processing node.
Processing is carved out of harvest as its own destination.
The Sankey confirms this structure — three parallel chains (crops, meat, animal products) merge at the end.
This is unverifiable from LSMS-ISA survey data. See `FLAGS_REVIEW.md` and `backlog.md B05`.

### Feed units — mixed units unresolvable
feed_total = feed_crops_kg_fresh + feed_liveweight_kg_DM
These are not comparable units. Correction requires per-crop DM conversion factors
that the survey does not record. Decision: sum as-is, flag clearly, do not cite absolute totals as DM.
See `backlog.md B08`.

### Milk unit conversion
1 litre = 1.03 kg (FAO convention). Applied in `clean/milk.R` as final step before saveRDS.
All downstream quantities are in kg. See `FLAGS_REVIEW.md`.

### Structural zeros vs missing data
Participation flags in `household_roster.R` are ground truth.
If grew_crops == FALSE → harvest = 0 (structural zero, not missing).
If owned_animals == FALSE → animal quantities = 0 (structural zero, not missing).
NAs in quantities where participation == TRUE are genuinely missing → imputed or excluded.

### Exclusions
Exclusions stand as in the original thesis. Not yet sensitivity-tested.
This is a known methodological limitation — see `backlog.md B01`.

### B04 — Weighting scripts
**Priority:** Medium | **Affects:** Project 01

### B05 — Processed crops extraction rate sensitivity
**Priority:** Medium | **Affects:** Project 01 mass balance and MFA input
Extraction rates (e.g. 72% flour yield from maize) are literature-derived.
Run mass balance and MFA with ±10% rate variation.
Also: processing waste currently assumed zero — add 2–3% moisture/spillage loss.

### B06 — Unclassified items in item_groups.csv
**Priority:** Low | **Affects:** Projects 01, 03
~40 items have no MFA group. Confirm which appear in households.rds.
Assign groups or document exclusion rationale for each.

### B07 — item_groups.csv master file structure
**Priority:** Low (post-portfolio) | **Affects:** Projects 01, 02, 03
Single master reference file across all projects with project-specific inclusion flags.
See `data/reference/item_groups_README.md` for proposed structure.

### B08 — Feed dry matter conversion
**Priority:** Low | **Affects:** Project 01 Sankey, MFA input feed variables
Feed quantities are mixed units (fresh weight + dry matter).
Revisit if future survey waves record which crops are fed to animals.

### B09 — crops–destinations misalignment profiling
**Priority:** Medium | **Affects:** Project 01 completeness
Anti-join stubs are in `05_exclusions_audit.R`. Run and document actual counts.
Determine whether misalignment is systematic (data error) or expected (reporting behaviour).
